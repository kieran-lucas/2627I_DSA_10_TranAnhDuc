Dùng singly linked list và con trỏ first trỏ đến đỉnh stack. Mọi thao tác chèn/xóa đều ở đầu danh sách.

Nút mới trỏ tới oldfirst; không cần duyệt toàn bộ danh sách.

push(item)

Giữ oldfirst → tạo nút mới ở đầu → lưu item → cho next = oldfirst.

pop()

Giữ first.item → dịch first = first.next → trả về item đã lưu.

public class LinkedStack<Item> {
    private Node first;
    private int n;

    private class Node {
        Item item;
        Node next;
    }

    public boolean isEmpty() { return first == null; }
    public int size() { return n; }

    public void push(Item item) {
        Node oldFirst = first;
        first = new Node();
        first.item = item;
        first.next = oldFirst;
        n++;
    }

    public Item pop() {
        if (isEmpty()) throw new java.util.NoSuchElementException();
        Item item = first.item;
        first = first.next;
        n--;
        return item;
    }
}

Tại sao O(1)? Chỉ cập nhật một số hữu hạn con trỏ, không đi qua các nút còn lại. push, pop, isEmpty đều O(1) trong trường hợp xấu nhất. Bộ nhớ tăng tuyến tính O(N); mỗi nút có overhead cho object và con trỏ. Trong mô hình bộ nhớ được phân tích ở bài, khoảng 40N byte cho N nút (không tính chính các chuỗi).

3. Stack bằng mảng dung lượng cố định

Lưu N phần tử trong s[0..N−1]. Biến N đồng thời là số phần tử hiện có và chỉ số vị trí sẽ ghi tiếp theo.

Đỉnh là s[N−1] = s[3]. Khi push(E), ghi vào s[4], rồi tăng N thành 5.
private String[] s;
private int N = 0;

public void push(String item) {
    s[N++] = item;      // dùng N làm index, sau đó N++
}

public String pop() {
    String item = s[--N]; // giảm N trước, rồi đọc s[N]
    s[N] = null;          // bỏ tham chiếu không còn dùng
    return item;
}

s[N++] và s[--N]: một bên tăng sau khi truy cập, bên kia giảm trước khi truy cập. Với stack rỗng, pop() cần xử lý underflow; với mảng đã đầy, push() gây overflow nếu không hỗ trợ tăng dung lượng.

Loitering: nếu chỉ giảm N mà không gán s[N] = null, ô cũ vẫn giữ tham chiếu đến đối tượng. Bộ thu gom rác không thể giải phóng đối tượng chỉ vì nó không còn nằm trong phần stack logic.

4. Resizing Array — tự động tăng/giảm sức chứa

Mảng có kích thước cố định, nhưng có thể thay cả mảng bằng mảng mới lớn hoặc nhỏ hơn. Vấn đề là khi nào cần resize để tránh sao chép liên tục.

Tăng dung lượng: nhân đôi khi đầy

Nếu N == s.length, tạo mảng mới gấp đôi và chép N phần tử. Nếu tăng thêm đúng một ô mỗi lần push, lần thêm thứ k có thể phải sao chép k−1 phần tử, dẫn tới tổng chi phí O(M²) cho M lần thêm.

Giảm dung lượng: chỉ khi đầy 1/4

Thu nhỏ ngay lúc mảng mới đầy 1/2 dễ gây thrashing: cứ pop rồi push quanh ngưỡng sẽ phải thu nhỏ và mở rộng liên tiếp. Quy tắc ổn định hơn là gấp đôi khi đầy; chia đôi khi N bằng 1/4 capacity.

Sau một lần resize, số phần tử phải thay đổi đáng kể trước khi xảy ra resize ngược lại.
public class ResizingArrayStack<Item> {
    private Item[] s = (Item[]) new Object[1];
    private int N = 0;

    public boolean isEmpty() { return N == 0; }
    public int size() { return N; }

    private void resize(int capacity) {
        Item[] copy = (Item[]) new Object[capacity];
        for (int i = 0; i < N; i++) copy[i] = s[i];
        s = copy;
    }

    public void push(Item item) {
        if (N == s.length) resize(2 * s.length);
        s[N++] = item;
    }

    public Item pop() {
        if (isEmpty()) throw new java.util.NoSuchElementException();
        Item item = s[--N];
        s[N] = null;
        if (N > 0 && N == s.length / 4) resize(s.length / 2);
        return item;
    }
}

Vì sao thời gian trung bình dàn trải là O(1)?

Một lần push/pop thông thường tốn O(1), còn lần gây resize có thể tốn O(N) do chép N phần tử. Tuy nhiên, các lần copy khi nhân đôi có kích thước tăng theo cấp số nhân 1 + 2 + 4 + ... < 2M khi thực hiện M lần thêm. Ngưỡng giảm 1/4 cũng tránh resize liên tiếp.

Vì vậy, từ stack rỗng, một chuỗi M thao tác tốn tổng O(M): mỗi thao tác có chi phí amortized O(1), không phải worst-case O(1).

Thao tácWorst-caseAmortized

Amortized ≠ average-case theo xác suất. Đó là chi phí bình quân trên một chuỗi thao tác ngay cả khi chuỗi được chọn theo trường hợp xấu. Với stack không rỗng, chính sách này giữ mảng sử dụng khoảng 25–100% dung lượng (bỏ qua chi tiết làm tròn). Theo mô hình tham chiếu 8 byte, mảng cấp phát tốn khoảng 8N–32N byte, chưa tính dữ liệu của đối tượng; những con số byte phụ thuộc JVM và kiến trúc.

5. Queue bằng linked list và mảng vòng

Queue phải thêm ở cuối và xóa ở đầu. Hai vị trí hoạt động độc lập nên cần chú ý đặc biệt khi chuyển từ rỗng ↔ có phần tử.

Linked Queue: first và last

first trỏ tới phần tử được lấy tiếp theo; last trỏ tới phần tử vừa thêm. enqueue nối nút mới sau last, dequeue bỏ nút first. Cả hai O(1) worst-case.

dequeue() trả A; enqueue(D) nối D vào sau C. last luôn trỏ tới nút cuối.

public class LinkedQueue<Item> {
    private Node first, last;
    private int n;

    private class Node {
        Item item;
        Node next;
    }

    public boolean isEmpty() { return first == null; }
    public int size() { return n; }

    public void enqueue(Item item) {
        Node oldLast = last;
        last = new Node();
        last.item = item;
        if (isEmpty()) first = last;
        else oldLast.next = last;
        n++;
    }

    public Item dequeue() {
        if (isEmpty()) throw new java.util.NoSuchElementException();
        Item item = first.item;
        first = first.next;
        if (isEmpty()) last = null;
        n--;
        return item;
    }
}

Hai trường hợp biên không được quên: enqueue trên queue rỗng phải đặt first = last; dequeue phần tử cuối phải đặt last = null. Nếu không, cấu trúc có thể giữ con trỏ không còn hợp lệ.

Mảng vòng (circular queue)

Giữ head ở phần tử đầu, tail ở ô trống sẽ ghi tiếp theo, N là số phần tử. Chỉ số tăng theo modulo sức chứa: (i + 1) % capacity. Nhờ đó, các ô đầu mảng được tái sử dụng mà không phải dịch toàn bộ phần tử.

// Sơ đồ logic cho queue mảng vòng với biến n, head, tail:
void enqueue(Item item) {
    if (n == q.length) resize(2 * q.length);
    q[tail] = item;
    tail = (tail + 1) % q.length;
    n++;
}

Item dequeue() {
    if (n == 0) throw new java.util.NoSuchElementException();
    Item item = q[head];
    q[head] = null;
    head = (head + 1) % q.length;
    n--;
    return item;
}

void resize(int capacity) {
    Item[] copy = (Item[]) new Object[capacity];
    for (int i = 0; i < n; i++)
        copy[i] = q[(head + i) % q.length];
    q = copy;
    head = 0;
    tail = n;
}

Khi resize queue vòng: phải chép theo thứ tự logic từ head, sau đó đặt head = 0, tail = N. Sao chép tuần tự từ q[0] có thể làm đảo thứ tự FIFO. Trong mã trên, q là mảng đã được khởi tạo với sức chứa dương.

6. Generics — dùng cùng cấu trúc cho nhiều kiểu

Thay vì viết riêng StackOfStrings, StackOfURLs, ..., dùng Stack<Item>. Trình biên dịch kiểm tra kiểu của push và pop ngay khi biên dịch.

Stack<String> names = new Stack<String>();
names.push("Ada");
String x = names.pop();       // không cần ép kiểu

Stack<Integer> numbers = new Stack<Integer>();
numbers.push(17);             // boxing: int -> Integer
int y = numbers.pop();       // unboxing: Integer -> int

Vì sao không dùng Object cho tất cả? Với stack Object, client phải ép kiểu thủ công. Nếu lấy một Orange và ép thành Apple, lỗi chỉ xuất hiện lúc chạy. Với Stack<Apple>, cố push một Orange bị chặn ngay lúc biên dịch.

Phân biệt cách tạo mảng generic
Item[] a = new Item[capacity];            // lỗi biên dịch
Item[] b = (Item[]) new Object[capacity]; // chạy được, unchecked cast
Việc dùng (Item[]) new Object[] liên quan đến type erasure; trình biên dịch có thể cảnh báo unchecked cast.

Autoboxing: tham số generic phải là kiểu tham chiếu (Integer, không phải int). Java tự đóng hộp/mở hộp ở push(17) và int a = pop().

7. Iterator, Iterable và vòng lặp foreach

Cho phép client duyệt các phần tử mà không cần biết stack đang dùng mảng hay linked list.

Khái niệmVai trò
Iterable<Item>Cung cấp phương thức iterator().
Iterator<Item>Cung cấp hasNext() và next() để duyệt.
for (Item x : structure)Cú pháp foreach, hoạt động thông qua iterator.
// Stack dùng linked list, với first là đỉnh:
public java.util.Iterator<Item> iterator() {
    return new java.util.Iterator<Item>() {
        private Node current = first;

        public boolean hasNext() {
            return current != null;
        }

        public Item next() {
            if (!hasNext())
                throw new java.util.NoSuchElementException();
            Item value = current.item;
            current = current.next;
            return value;
        }
    };
}

Để dùng trực tiếp foreach, lớp stack phải khai báo implements Iterable<Item> và cung cấp phương thức iterator(). Trong stack mảng lưu đáy → đỉnh ở s[0..N−1], muốn duyệt từ đỉnh xuống đáy thì đặt i = N và mỗi lần next() trả s[--i]. Với stack linked list, chỉ cần đi theo con trỏ next từ first.

Concurrent modification: khi client sửa cấu trúc trong lúc đang duyệt, một fail-fast iterator có thể ném ConcurrentModificationException. Muốn tự cài fail-fast cần đếm số lần sửa đổi (modification count), lưu số đếm khi tạo iterator và kiểm tra ở các lần duyệt. Không phải iterator nào cũng tự động fail-fast.

8. Ứng dụng: lời gọi hàm và biểu thức số học

Stack xuất hiện trong quản lý lời gọi hàm, phân tích cú pháp, Undo và đánh giá biểu thức. Hai ứng dụng quan trọng nhất của bài được minh họa dưới đây.

Call stack và đệ quy

Mỗi lần gọi hàm, chương trình cần lưu ngữ cảnh thực thi (tham số/biến cục bộ, địa chỉ quay lại...). Khi hàm kết thúc, khung ngăn xếp (stack frame) mới nhất được lấy ra trước. Với lời gọi đệ quy, các frame xếp chồng cho tới điều kiện dừng.

Đệ quy gcd(216, 192) — LIFO của khung gọi
gcd(216,192)→gcd(192,24)→gcd(24,0)

Tính tới điều kiện dừng: gcd(24,0) = 24; sau đó trả kết quả ngược theo thứ tự lời gọi.

Dijkstra's Two-Stack Algorithm

Với biểu thức infix có đủ dấu ngoặc và các toán tử được hỗ trợ, dùng hai stack: ops lưu toán tử, vals lưu toán hạng/kết quả trung gian. Quy tắc: gặp ( bỏ qua; gặp số → push vào vals; gặp toán tử → push vào ops; gặp ) → pop toán tử và hai số, tính rồi push kết quả trở lại vals.

Trace của ( 1 + ( ( 2 + 3 ) * ( 4 * 5 ) ) )

Bảng lược bỏ dấu ngoặc mở và các bước chỉ push trung gian; mỗi lần đóng ngoặc tương ứng với một phép tính.
// Input: các token đã tách, ví dụ ["(", "1", "+", ... ")"]
Stack<String> ops = new Stack<>();
Stack<Double> vals = new Stack<>();
for (String token : tokens) {
    if (token.equals("(")) continue;
    else if (token.equals("+") || token.equals("*"))
        ops.push(token);
    else if (token.equals(")")) {
        String op = ops.pop();
        double b = vals.pop();
        double a = vals.pop();
        if (op.equals("+")) vals.push(a + b);
        else vals.push(a * b);
    } else {
        vals.push(Double.parseDouble(token));
    }
}
double result = vals.pop();     // 101.0

Điều kiện phạm vi: ví dụ này giả định biểu thức đã được tách token, ngoặc đầy đủ và hợp lệ, và chỉ hỗ trợ +, *. Không được ngầm coi đây là bộ xử lý mọi biểu thức infix có độ ưu tiên và tính kết hợp. Nếu mở rộng sang phép trừ/chia, phải giữ đúng thứ tự a op b, trong đó b được pop trước.

Postfix / Reverse Polish Notation (RPN)

Đưa toán tử ra sau các toán hạng, ta không cần dấu ngoặc: 1 2 3 + 4 5 * * + cũng bằng 101. Duyệt từ trái sang phải: gặp số thì push; gặp toán tử thì pop hai giá trị, tính và push kết quả. Đây là cách đánh giá trực tiếp bằng một stack giá trị.

Java Collections: hiểu API trước khi dùng

ArrayList dựa trên mảng động, LinkedList dựa trên danh sách liên kết. java.util.Stack kế thừa Vector nên mang thêm nhiều thao tác không phù hợp với một API stack tối giản; thứ tự lặp của nó cũng có thể khác thứ tự pop. java.util.Queue là interface, không phải lớp queue cụ thể có thể khởi tạo trực tiếp.

Chọn cấu trúc dựa trên chi phí của thao tác thực tế, không chỉ dựa vào tên kiểu dữ liệu. Chẳng hạn, xóa tại vị trí bất kỳ trong ArrayList cần dời các phần tử phía sau, có thể tốn O(N). Với một danh sách ban đầu có N² phần tử, xóa ngẫu nhiên lần lượt tất cả phần tử có thể dẫn tới tổng O(N⁴); dùng thư viện sai cách đôi khi chậm hơn một giải pháp tưởng như đơn giản.

03. Vì sao không giảm dung lượng ở ngưỡng 1/2?
Gần ngưỡng đó, chuỗi push-pop liên tiếp có thể gây resize qua lại với mỗi thao tác.
04. O(1) amortized có đồng nghĩa mọi thao tác O(1)?
Không. Một thao tác resize riêng lẻ có thể O(N).
05. Queue rỗng enqueue(X) cần cập nhật những gì?
Đặt cả first và last trỏ đến nút X.
06. Queue xóa phần tử cuối có cần sửa last?
Có: sau khi first thành null, đặt last = null.
07. Mảng vòng có head=6, capacity=8, dequeue xong head mới?
(6 + 1) % 8 = 7.
08. Tại sao Item[] a = new Item[k] không biên dịch?
Java không cho tạo generic array trực tiếp; dạng (Item[]) new Object[k] gây cảnh báo unchecked cast.
09. Iterator stack mảng muốn theo LIFO chạy hướng nào?
Từ s[N−1] về s[0].
10. Hai-stack evaluator gặp dấu đóng ngoặc thì làm gì?
Pop một toán tử, hai toán hạng, tính rồi push kết quả vào stack giá trị.

12. Thứ tự hai giá trị pop quan trọng với phép trừ?
Có. Pop b trước, sau đó a; tính a − b.
