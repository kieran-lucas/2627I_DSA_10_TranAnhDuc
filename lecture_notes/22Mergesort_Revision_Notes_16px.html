1. Merge — trộn hai đoạn đã có thứ tự

Bài toán: cho hai đoạn a[lo..mid] và a[mid+1..hi] đã được sắp xếp tăng dần. Hãy kết hợp chúng thành a[lo..hi] có thứ tự. Đây là thao tác cốt lõi của Merge Sort.

Hai con trỏ i = lo và j = mid+1 lần lượt chỉ phần tử chưa lấy đầu tiên của mỗi nửa. Con trỏ k chạy qua vùng kết quả; mỗi bước lấy phần tử nhỏ hơn ở đầu hai nửa, rồi tăng con trỏ tương ứng.

1.2. Cài đặt Java

private static <T extends Comparable<? super T>> void merge(
        T[] a, T[] aux, int lo, int mid, int hi) {
    for (int k = lo; k <= hi; k++) aux[k] = a[k];

    int i = lo, j = mid + 1;
    for (int k = lo; k <= hi; k++) {
        if      (i > mid)                    a[k] = aux[j++];
        else if (j > hi)                     a[k] = aux[i++];
        else if (aux[j].compareTo(aux[i]) < 0) a[k] = aux[j++];
        else                                a[k] = aux[i++];
    }
}
  • Vì sao cần aux[]? Nếu ghi đè trực tiếp lên a[] trong khi còn phải đọc hai nửa, một phần tử chưa xử lý có thể bị mất. Bản sao aux[lo..hi] bảo vệ dữ liệu đầu vào của lần trộn.
  • Bốn nhánh của vòng for: trái hết → lấy phải; phải hết → lấy trái; phải nhỏ hơn → lấy phải; còn lại → lấy trái (kể cả trường hợp bằng nhau).
  • Bất biến của vòng trộn: trước khi ghi a[k], các vị trí a[lo..k−1] đã là k−lo phần tử nhỏ nhất, đúng thứ tự; i và j chỉ các đầu phần chưa dùng.
  • Về bộ nhớ: kết quả được ghi trở lại chính mảng a[], nhưng hàm vẫn dùng aux[] kích thước tuyến tính; do đó đây không phải merge in-place theo nghĩa tiết kiệm bộ nhớ phụ.

Không được đảo điều kiện khi hai khóa bằng nhau. Nếu dùng <= 0 để lấy phần tử bên phải trong nhánh so sánh, thứ tự ban đầu của hai phần tử có khóa bằng nhau có thể bị đảo.

2. Top-down Merge Sort — chia để trị

Ý tưởng: chia mảng thành hai nửa, đệ quy sắp mỗi nửa, sau đó gọi merge() để thu được toàn bộ đoạn có thứ tự. Đoạn dài 0 hoặc 1 đã có thứ tự nên không cần xử lý.

Cây chia để trị: 8 → 4 → 2 → 1, sau đó trộn ngược lên

Chiều đi xuống: chia đoạn. Chiều đi lên: hai con đã sắp xếp, mới được trộn thành cha.

2.2. Code Java top-down hoàn chỉnh

public final class MergeSort {
    private MergeSort() { }

    private static <T extends Comparable<? super T>> void merge(
            T[] a, T[] aux, int lo, int mid, int hi) {
        for (int k = lo; k <= hi; k++) aux[k] = a[k];
        int i = lo, j = mid + 1;
        for (int k = lo; k <= hi; k++) {
            if      (i > mid) a[k] = aux[j++];
            else if (j > hi)  a[k] = aux[i++];
            else if (aux[j].compareTo(aux[i]) < 0) a[k] = aux[j++];
            else a[k] = aux[i++];
        }
    }

    private static <T extends Comparable<? super T>> void sort(
            T[] a, T[] aux, int lo, int hi) {
        if (hi <= lo) return;
        int mid = lo + (hi - lo) / 2;
        sort(a, aux, lo, mid);
        sort(a, aux, mid + 1, hi);
        merge(a, aux, lo, mid, hi);
    }

    public static <T extends Comparable<? super T>> void sort(T[] a) {
        T[] aux = a.clone();
        sort(a, aux, 0, a.length - 1);
    }

    public static <T extends Comparable<? super T>> void sortBottomUp(T[] a) {
        int n = a.length;
        T[] aux = a.clone();
        for (int sz = 1; sz < n; sz *= 2)
            for (int lo = 0; lo < n - sz; lo += 2 * sz)
                merge(a, aux, lo, lo + sz - 1,
                      Math.min(lo + 2 * sz - 1, n - 1));
    }
}

Ý nghĩa mid = lo + (hi - lo)/2: tính trung điểm an toàn hơn so với (lo + hi)/2 khi lo + hi có nguy cơ tràn số nguyên.

3. Phân tích thời gian và bộ nhớ

3.1. Tại sao lại là N log N?

Gọi T(N) là lượng công việc trên mảng N phần tử. Mỗi lần tách thành hai nửa tốn hai lời gọi đệ quy; việc trộn hai nửa đã sắp cần thời gian tuyến tính theo độ dài đoạn.

T(N) = 2T(N/2) + Θ(N), T(1) = Θ(1)

Best case của số lần so sánh

Với hai nửa lần lượt toàn nhỏ hơn toàn lớn hơn, mỗi merge chỉ cần m so sánh nếu m = kích thước nửa trái = n/2, vì sau đó một nửa hết.

N = 2ᵏ: mỗi tầng khoảng N/2 so sánh, có log₂N tầng.

Worst case của số lần so sánh

Hai nửa có khóa đan xen nên merge có thể cần tối đa m+n−1 so sánh (với cả hai nửa không rỗng).

Với N = 2ᵏ: N log₂N − N + 1 là cận cực đại đạt được.

Phân biệt: số lần so sánh không phải số lần ghi/chuyển phần tử. Ngay cả khi phần tử hai nửa đã theo đúng thứ tự, phiên bản top-down cơ bản vẫn sao chép và trộn ở mọi tầng. Do đó best-case về thời gian vẫn Θ(N log N), dù số phép so sánh có thể thấp hơn hệ số.

4. Ba cải tiến thường gặp của Merge Sort

4.1. Dùng Insertion Sort cho các đoạn nhỏ

Đệ quy và cấp phát/đọc ghi tạo overhead đáng kể khi đoạn chỉ có ít phần tử. Thay vì chia tiếp, dùng Insertion Sort trực tiếp cho đoạn có kích thước nhỏ (ví dụ khoảng 10).

if (hi - lo + 1 <= CUTOFF) {
    insertionSortRange(a, lo, hi);
    return;
}

4.2. Bỏ qua merge khi hai nửa đã nối thành dãy tăng dần

Sau khi đã sắp xếp hai nửa, chỉ cần kiểm tra phần tử cuối bên trái và đầu bên phải. Nếu a[mid] ≤ a[mid+1], cả đoạn đã có thứ tự, không cần trộn.

sort(a, aux, lo, mid);
sort(a, aux, mid + 1, hi);
if (a[mid].compareTo(a[mid + 1]) <= 0) return;
merge(a, aux, lo, mid, hi);

Không hiểu nhầm: chỉ có kiểm tra a[mid] ≤ a[mid+1] sau khi mỗi nửa đã được sắp xếp. Nếu áp dụng sớm cho hai nửa chưa sắp, điều kiện này không đủ kết luận cả đoạn có thứ tự.

4.3. Luân phiên vai trò mảng nguồn và đích

Trong cách cơ bản, mỗi lần merge chép a[lo..hi] sang aux[], rồi chép ngược về a[]. Cải tiến là dùng hai mảng luân phiên: lời gọi đệ quy sắp từ mảng này sang mảng kia, rồi merge từ nguồn sang đích.

// Dạng lõi: source/destination hoán đổi qua từng mức.
sort(destination, source, lo, mid);
sort(destination, source, mid + 1, hi);
mergeFromTo(source, destination, lo, mid, hi);

Cải tiến này tiết kiệm các lượt sao chép trong mỗi lần merge nhưng không giảm bộ nhớ phụ từ Θ(N). Cần khởi tạo mảng nguồn/đích nhất quán ngay từ đầu để tránh đọc ô chưa có giá trị.

5.1. Code Java (dùng lại hàm merge ở mục 2)

public static <T extends Comparable<? super T>> void sortBottomUp(T[] a) {
    int n = a.length;
    T[] aux = a.clone();
    for (int sz = 1; sz < n; sz *= 2) {
        for (int lo = 0; lo < n - sz; lo += 2 * sz) {
            int mid = lo + sz - 1;
            int hi = Math.min(lo + 2 * sz - 1, n - 1);
            merge(a, aux, lo, mid, hi);
        }
    }
}

6. Natural Mergesort và Timsort

6.1. Run tự nhiên là gì?

Run: một đoạn liên tiếp của mảng đã có thứ tự. Natural mergesort quét để tìm các run đang có, thay vì luôn coi mỗi phần tử là một run độ dài 1. Nó trộn các run kề nhau và lặp lại.

Đánh đổi: ít lượt trộn hơn khi đầu vào gần có thứ tự, nhưng phải tốn phép so sánh để dò vị trí bắt đầu/kết thúc run.

6.2. Timsort

Timsort là phiên bản adaptive, stable, natural mergesort: phát hiện run có sẵn, có thể dùng Binary Insertion Sort để kéo dài các run ngắn, rồi trộn các run bằng những quy tắc tối ưu. Với nhiều mảng có cấu trúc sẵn, Timsort có thể chạy tuyến tính.

  • Best case: Θ(N) trên các đầu vào thích hợp có run dài; worst case: O(N log N).
  • Ổn định: giữ thứ tự tương đối của các phần tử có khóa bằng nhau.
  • Không cần học toàn bộ chi tiết hiện thực: ghi nhớ điểm khác biệt cốt lõi là tận dụng các run tự nhiên, khác với mergesort chuẩn cứ chia/trộn theo kích thước cố định.

7. Độ phức tạp của bài toán sắp xếp: cận dưới

Mô hình so sánh (comparison-based sorting): thuật toán biết thứ tự giữa hai phần tử chỉ bằng các phép so sánh khóa, mỗi phép so sánh tạo một nhánh Đúng/Sai. Tổng số phép so sánh tệ nhất tương ứng với độ sâu lớn nhất của cây quyết định.

Cây quyết định cho ba khóa phân biệt a, b, c

Mỗi lá tương ứng một trật tự có thể xảy ra. Ở N = 3 cần phân biệt 3! = 6 trường hợp; độ sâu tệ nhất ít nhất ⌈log₂6⌉ = 3.

7.1. Chứng minh cận dưới Ω(N log N)

Với N khóa đôi một khác nhau, tồn tại N! cách sắp đầu vào. Cây quyết định đúng phải có ít nhất N! lá để phân biệt các trường hợp. Một cây nhị phân độ cao h có nhiều nhất 2ʰ lá.

2ʰ ≥ N! ⇒ h ≥ ⌈log₂(N!)⌉ = Ω(N log N)

Bằng công thức Stirling, log₂(N!) = N log₂N − (log₂e)N + O(log N). Vì mergesort đạt O(N log N) so sánh trong worst case nên nó tối ưu về bậc số phép so sánh trong mô hình này.

Giới hạn phạm vi: chứng minh trên áp dụng khi chỉ lấy thông tin qua so sánh khóa tổng quát và xét worst case. Nếu biết thêm về miền giá trị, cấu trúc khóa hoặc đầu vào có trật tự sẵn, thuật toán đặc thù (ví dụ radix sort) có thể vượt mốc N log N về thời gian; điều đó không mâu thuẫn với cận dưới.

Đặc biệt, “tối ưu về số phép so sánh” không đồng nghĩa tối ưu về bộ nhớ: Merge Sort vẫn dùng mảng phụ Θ(N).

8. Comparable và Comparator trong Java

Một kiểu dữ liệu có thể có thứ tự tự nhiên (natural order) và đồng thời nhiều thứ tự thay thế tùy mục đích. Việc tách đối tượng dữ liệu khỏi tiêu chí so sánh cho phép dùng lại một thuật toán sắp xếp.

8.1. Một lớp Student, nhiều tiêu chí

import java.util.Arrays;
import java.util.Comparator;

class Student {
    final String name;
    final int section;
    Student(String name, int section) {
        this.name = name;
        this.section = section;
    }
    static final Comparator<Student> BY_NAME =
        (x, y) -> x.name.compareTo(y.name);
    static final Comparator<Student> BY_SECTION =
        (x, y) -> Integer.compare(x.section, y.section);
}

// Chọn một trong hai thứ tự:
Arrays.sort(students, Student.BY_NAME);
Arrays.sort(students, Student.BY_SECTION);

Mỗi comparator cần đưa ra quan hệ thứ tự nhất quán và bắc cầu. Dùng Integer.compare(x.section, y.section) tránh nguy cơ tràn số so với viết phép trừ khi trường dữ liệu có thể rất lớn. Trong ví dụ section nhỏ của slide, phép trừ đơn giản cũng hoạt động.

9. Stability — tính ổn định khi sắp xếp

Thuật toán ổn định: nếu hai phần tử có khóa so sánh bằng nhau, thứ tự xuất hiện tương đối của chúng sau sắp xếp vẫn giống trước đó. Không đòi hai phần tử phải là cùng một đối tượng.

9.1. Ví dụ hai lần sắp xếp dữ liệu

Giả sử các sinh viên đã được sắp theo tên. Nếu tiếp tục sắp theo lớp (section) bằng thuật toán ổn định, mỗi lớp sẽ có thứ tự theo tên như trước; nếu dùng thuật toán không ổn định, thứ tự tên trong cùng lớp có thể bị phá.

Khóa bằng nhau phải giữ nguyên thứ tự
B₁AB₂
→
AB₁B₂

Thứ tự B₁ trước B₂ được giữ dù hai phần tử cùng khóa B. Với Selection Sort, ví dụ [B₁, B₂, A] lại có thể thành [A, B₂, B₁] và mất ổn định.

11. Câu hỏi tự kiểm tra

1. Hai nửa chưa có thứ tự thì gọi merge() được không?
Không. Merge chỉ đúng nếu từng nửa đã sắp xếp.
2. Vì sao khi aux[i] và aux[j] bằng nhau phải lấy bên trái?
Để bảo toàn thứ tự tương đối của những phần tử có cùng khóa (stable).
3. Merging [2, 5] và [1, 3, 6] cho kết quả gì?
[1, 2, 3, 5, 6]; mỗi bước lấy giá trị nhỏ hơn ở đầu hai nửa.
4. Top-down: merge(0, 3, 7) diễn ra trước hay sau các merge con?
Sau khi các đoạn 0..3 và 4..7 đã được sắp xếp.
5. Vì sao T(N) = 2T(N/2) + Θ(N)?
Hai bài toán con nửa kích thước và một lượt trộn tuyến tính.
6. Merge Sort có chạy O(N) trên mảng đã sắp theo code cơ bản không?
Không; bản cơ bản vẫn Θ(N log N). Có thể tối ưu bằng kiểm tra ranh giới để bỏ lượt trộn.
7. Với N = 8, có bao nhiêu tầng merge?
log₂8 = 3 tầng.
8. Bottom-up N lẻ cần xử lý thế nào?
Giữ đoạn lẻ còn lại; chặn hi = min(lo + 2sz − 1, N − 1).
9. So sánh số bộ nhớ Merge và Shellsort?
Merge dùng Θ(N) bộ nhớ phụ, Shellsort in-place dùng O(1).
10. Vì sao cận dưới Ω(N log N) không cấm Counting/Radix Sort?
Vì cận dưới chỉ áp dụng cho mô hình so sánh khóa tổng quát.
11. Comparable khác Comparator thế nào?
Comparable xác định thứ tự tự nhiên; Comparator cung cấp tiêu chí thay thế.
12. Sắp theo tên rồi theo lớp: cần thuật toán gì để giữ tên trong cùng lớp?
Một thuật toán ổn định ở lần sắp theo lớp, ví dụ Merge Sort.
