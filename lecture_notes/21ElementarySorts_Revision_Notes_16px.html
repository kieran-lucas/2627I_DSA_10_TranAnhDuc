1. Bài toán sắp xếp và phép so sánh

Sorting: sắp lại N phần tử (items) theo một khóa (key) và một thứ tự xác định. Phần tử có thể là bản ghi gồm nhiều trường; chỉ khóa được dùng để so sánh, nhưng cả bản ghi phải di chuyển cùng nhau. Ví dụ: sắp bản ghi sinh viên theo họ tên.

Total order — thứ tự toàn phần. Quan hệ ≤ phải có: phản đối xứng (a ≤ b và b ≤ a ⇒ a = b), bắc cầu (a ≤ b, b ≤ c ⇒ a ≤ c) và so sánh được (a ≤ b hoặc b ≤ a). Nếu so sánh không bắc cầu, thuật toán sắp xếp có thể cho kết quả không nhất quán.

1.1. Java Comparable và callback

Hàm sort() không cần biết đối tượng là String, Double hay Date. Thay vào đó, nó gọi compareTo() mà kiểu dữ liệu đã cài đặt thông qua interface Comparable<T>.

Điều kiệnv.compareTo(w)Ý nghĩa

Hai khóa bằng nhau0v = w theo tiêu chí so sánh

Ví dụ với ngày tháng: so năm → tháng → ngày, chỉ xét trường tiếp theo nếu trường trước bằng nhau. Khi tự định nghĩa Comparable cho một kiểu Date, có thể triển khai như sau:

public int compareTo(Date that) {
    if (this.year  != that.year)  return Integer.compare(this.year, that.year);
    if (this.month != that.month) return Integer.compare(this.month, that.month);
    return Integer.compare(this.day, that.day);
}

Hai hàm trợ giúp của các thuật toán sắp xếp dùng compareTo() và hoán đổi toàn bộ phần tử:

private static boolean less(Comparable v, Comparable w) {
    return v.compareTo(w) < 0;
}
private static void exch(Comparable[] a, int i, int j) {
    Comparable temp = a[i];
    a[i] = a[j];
    a[j] = temp;
}

Cần phân biệt: compareTo() quyết định thứ tự theo khóa; exch() đổi chỗ cả phần tử. Cùng một thuật toán sắp xếp có thể áp dụng cho nhiều kiểu dữ liệu nếu phép so sánh hợp lệ.

2. Selection Sort — Sắp xếp chọn

Ý tưởng: tại vị trí i, tìm phần tử nhỏ nhất trong đoạn chưa sắp xếp a[i..N-1], rồi đổi chỗ với a[i]. Sau mỗi lượt, thêm một phần tử vào đúng vị trí cuối cùng.

Bất biến: trước lượt i, đoạn a[0..i-1] đã tăng dần, gồm i khóa nhỏ nhất và sẽ không bị thay đổi ở các lượt sau. Phần chưa xử lý nằm ở a[i..N-1].

2.1. Java

public static void selectionSort(Comparable[] a) {
    int n = a.length;
    for (int i = 0; i < n; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++) {
            if (less(a[j], a[min])) min = j;
        }
        exch(a, i, min);
    }
}

2.2. Đếm phép toán và tính chất

Comparisons = (N−1) + (N−2) + … + 1 = N(N−1)/2 ∼ N²/2
  • Thời gian: best = average = worst = Θ(N²), vì mọi lượt đều quét toàn bộ phần còn lại, kể cả khi mảng đã có thứ tự.
  • Đổi chỗ: N lần gọi exch() trong đoạn code trên (kể cả tự đổi với chính mình); tức O(N) phép đổi chỗ.
  • Bộ nhớ phụ: O(1), sắp xếp tại chỗ.
  • Không ổn định (unstable): với các khóa bằng nhau, đổi chỗ xa có thể đảo thứ tự ban đầu. Ví dụ [2ₐ, 2ᵦ, 1] → [1, 2ᵦ, 2ₐ].

Nhớ nhanh: Selection Sort ít đổi chỗ nhưng luôn so sánh bậc hai. Hai con số này không được đánh đồng.

3. Insertion Sort — Sắp xếp chèn

Ý tưởng: xem a[0..i-1] là đoạn đã tăng dần; lấy a[i], di chuyển về trái qua các phần tử lớn hơn nó cho tới đúng chỗ. Trong bản cài đặt gốc, việc di chuyển được thực hiện bằng đổi chỗ hai phần tử kề nhau.

Bất biến: sau khi xử lý vị trí i, đoạn a[0..i] tăng dần; nhưng các phần tử trong đoạn này chưa chắc ở vị trí cuối cùng, vì có thể còn phần tử nhỏ hơn xuất hiện bên phải.

3.1. Java

public static void insertionSort(Comparable[] a) {
    int n = a.length;
    for (int i = 1; i < n; i++) {
        for (int j = i; j > 0; j--) {
            if (less(a[j], a[j - 1]))
                exch(a, j, j - 1);
            else break;
        }
    }
}

3.2. Best, average, worst

Vì với mỗi cặp khóa phân biệt, xác suất bị đảo là 1/2, số nghịch thế kỳ vọng bằng N(N−1)/4. Bởi số lần đổi chỗ bằng số nghịch thế, ta thu được ước lượng trung bình ∼ N²/4.

  • Bộ nhớ phụ: O(1), tại chỗ.
  • Ổn định (stable): chỉ đổi chỗ nếu khóa bên phải nhỏ hơn nghiêm ngặt khóa bên trái; phần tử có khóa bằng nhau không vượt qua nhau.
  • Thích nghi (adaptive): chạy nhanh khi đầu vào đã gần có thứ tự.

Lưu ý khi đếm: với đoạn code trên, số phép so sánh = số lần đổi chỗ + số lượt chèn dừng bởi một phép so sánh sai. Phần cộng thêm không quá N−1; khi phần tử chạy đến đầu mảng, không có phép so sánh sai cuối cùng.

4. Inversions và những cải tiến của Insertion Sort

Inversion — cặp nghịch thế: một cặp chỉ số i < j nhưng a[i] > a[j]. Mảng tăng dần có 0 nghịch thế; mảng N khóa phân biệt giảm dần có N(N−1)/2 nghịch thế.

Số lần đổi chỗ kề nhau của Insertion Sort = số nghịch thế ban đầu I

Mỗi lần đổi chỗ hai phần tử kề nhau đang ngược thứ tự sẽ giảm đúng một nghịch thế. Do đó, thời gian Insertion Sort là Θ(N + I) nếu tính các bước quét vòng lặp và đổi chỗ. Khi I = O(N), thời gian trở thành Θ(N).

Half exchanges (dịch phần tử)

Lưu khóa cần chèn trong biến tạm; dịch các phần tử lớn hơn sang phải rồi đặt khóa vào vị trí trống. Giảm số phép ghi/trao đổi so với hoán đổi liên tiếp, nhưng độ phức tạp tiệm cận không đổi.

Binary insertion sort

Dùng Binary Search trên đoạn đã sắp xếp để tìm vị trí chèn. Số so sánh có thể còn O(N log N), nhưng vẫn phải dịch O(N²) phần tử trong trường hợp xấu nhất.

Bẫy thường gặp: giảm số phép so sánh không tự động giảm thời gian chạy xuống O(N log N). Với mảng, dịch phần tử cũng tốn chi phí; thuật toán cần xét tổng chi phí.

5. Shellsort — Sắp xếp theo bước nhảy

Ý tưởng: Insertion Sort chỉ chuyển phần tử từng ô; Shellsort cho phép chuyển xa hơn bằng cách lần lượt h-sort mảng theo các khoảng cách giảm dần h. Lượt cuối cùng luôn là h = 1 (chính là Insertion Sort).

h-sorted nghĩa là gì? Mỗi dãy con có chỉ số cách nhau h vị trí đều tăng dần: a[r], a[r+h], a[r+2h], ... với 0 ≤ r < h. Đây là h dãy đan xen, không phải h đoạn liên tiếp.

5.1. Chọn bước nhảy h

Một dãy bước nhảy thường dùng là 3h + 1: 1, 4, 13, 40, 121, .... Bắt đầu từ h lớn nhất thích hợp, sau mỗi lượt đặt h = h / 3 (chia nguyên). Lựa chọn khoảng cách ảnh hưởng mạnh đến hiệu năng: dãy lũy thừa 2 đơn thuần kém; dãy Sedgewick cũng được xem xét.

5.2. Java (dãy 3h + 1)

public static void shellSort(Comparable[] a) {
    int n = a.length;
    int h = 1;
    while (h < n / 3) h = 3 * h + 1;

    while (h >= 1) {
        for (int i = h; i < n; i++) {
            for (int j = i;
                 j >= h && less(a[j], a[j - h]);
                 j -= h) {
                exch(a, j, j - h);
            }
        }
        h /= 3;
    }
}

Mỗi lượt là Insertion Sort trên những dãy con đan xen với khoảng cách h. Các lượt h lớn giúp đưa phần tử về gần vị trí thích hợp; khi h giảm, đoạn cần dịch thường ngắn hơn. Một tính chất quan trọng: mảng đã h-sorted vẫn h-sorted sau một lượt g-sort khác, dù chứng minh tính chất này không hiển nhiên.

5.3. Phân tích và tính chất

  • Với dãy 3h + 1, cận trên số so sánh ở worst case là O(N3/2).
  • Trong trường hợp mảng đã tăng dần, các lượt vẫn quét các chỉ số theo h: Θ(N log N) với dãy này (tổng qua các bước h).
  • Thời gian trung bình khó biểu diễn bằng một công thức chính xác; kết quả phụ thuộc dãy bước nhảy.
  • O(1) bộ nhớ phụ; không ổn định vì đổi chỗ các phần tử cách xa nhau có thể đảo thứ tự những khóa bằng nhau. Chẳng hạn [1,2ₐ,1,1,2ᵦ,1] sau lượt h=4 thành [1,1,1,1,2ᵦ,2ₐ].

Nhớ: ở lượt h > 1, mảng chưa chắc tăng dần khi nhìn từ trái sang phải; điều cần kiểm tra là từng dãy con có bước h đã có thứ tự hay chưa. Kết thúc bằng h = 1 mới đảm bảo cả mảng có thứ tự.

6. Shuffling — Hoán vị ngẫu nhiên đồng đều

Khác với sorting, shuffling muốn mỗi hoán vị của N phần tử phân biệt xuất hiện với xác suất như nhau: 1/N!. Mục tiêu là sự đồng đều của phân phối xác suất, không chỉ là trông “có vẻ ngẫu nhiên”.

6.1. Shuffle Sort

Gán cho mỗi phần tử một khóa ngẫu nhiên độc lập, rồi sắp xếp theo các khóa đó. Nếu khóa là các số thực liên tục độc lập, đồng phân phối và không có trùng khóa, mọi thứ tự là đồng xác suất. Độ phức tạp phụ thuộc thuật toán sắp xếp được dùng, không phải O(N) mặc định.

Không được tạo comparator trả về ngẫu nhiên cho từng lần so sánh. Một comparator như vậy có thể vi phạm bắc cầu và tính nhất quán của quan hệ thứ tự, nên gọi hàm sort không đảm bảo tạo hoán vị đều — thậm chí có thể làm thuật toán so sánh bị lỗi.

6.2. Knuth / Fisher–Yates Shuffle

Duyệt từ trái sang phải. Ở bước i, chọn r đều trong các số nguyên từ 0 đến i (bao gồm hai đầu), rồi đổi a[i] và a[r].

public static void shuffle(Object[] a) {
    for (int i = 0; i < a.length; i++) {
        int r = StdRandom.uniform(i + 1); // 0..i
        Object temp = a[i];
        a[i] = a[r];
        a[r] = temp;
    }
}

Ở bước i, phần tử thứ i được đưa vào một trong i+1 vị trí đầu, mọi lựa chọn có cùng xác suất. Sau N bước, thuật toán có đúng 1×2×...×N = N! chuỗi lựa chọn đồng xác suất, tương ứng một-một với N! hoán vị.

P(mỗi hoán vị) = 1/(1×2×…×N) = 1/N! · Thời gian Θ(N) · Bộ nhớ O(1)

Biến thể tương đương: duyệt i = 0..N-1, chọn r đều trong [i, N-1] (cũng là Fisher–Yates tiến). Không được trộn hai quy tắc chỉ số với nhau.

6.3. Vì sao chọn r từ 0 đến N−1 ở mọi bước là sai?

Với N = 3, cách làm sai có 3³ = 27 chuỗi lựa chọn đều nhau, nhưng chỉ có 3! = 6 hoán vị. Xác suất các kết quả không bằng 1/6:

8. Câu hỏi tự kiểm tra

1. Vì sao Selection Sort vẫn Θ(N²) trên mảng đã sắp?
Vì vòng tìm min quét toàn bộ phần chưa xử lý ở mọi lượt.
2. Selection Sort gọi bao nhiêu lần exch()?
Đúng N lần trong code đã cho, kể cả tự đổi chỗ với chính mình.
3. Đoạn đã sắp trong Insertion Sort đã cố định chưa?
Chưa. Phần tử nhỏ hơn xuất hiện sau vẫn có thể đẩy chúng sang phải.
4. Với I nghịch thế, Insertion Sort đổi chỗ mấy lần?
Đúng I lần nếu dùng các phép đổi chỗ kề nhau trên khóa nghiêm ngặt.
5. Vì sao mảng gần có thứ tự làm Insertion nhanh?
Ít nghịch thế ⇒ ít đổi chỗ, độ phức tạp Θ(N + I).
6. Binary insertion đã là O(N log N) toàn bộ chưa?
Chưa; số lần dịch chuyển trên mảng vẫn có thể Θ(N²).
7. Khi h = 4, những vị trí nào nằm chung nhóm?
Các chỉ số cách nhau 4: 0–4–8…, 1–5–9…, v.v.
8. Shellsort đã 4-sorted thì đã tăng dần chưa?
Không. Chỉ từng dãy con đan xen cách 4 vị trí được sắp xếp.
9. Selection / Insertion / Shell: thuật toán nào stable?
Insertion Sort ổn định với điều kiện chỉ đổi khi <, không phải ≤.
10. Xác suất mỗi kết quả của Knuth Shuffle là gì?
1/N!, nếu lấy ngẫu nhiên đều chính xác tại mỗi lượt.
11. Sai ở đâu nếu r luôn lấy 0..N−1?
Các hoán vị không đồng xác suất, dù vẫn có thể xuất hiện tất cả.
12. Vì sao comparator ngẫu nhiên không dùng để shuffle?
Vi phạm tính bắc cầu/nhất quán của quan hệ thứ tự; sort không có bảo đảm.
